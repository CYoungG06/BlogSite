# Kimi K3 技术报告:2.8T 开源旗舰的双轴扩展，与 OPD 的工业级落地

> 2026-07-31

## 一句话版本

Kimi K3 是 Moonshot 开源的 2.8T 参数 MoE 模型(每 token 激活 104B，原生视觉，1M token 上下文):架构上沿**序列、深度、宽度**三个维度重新设计信息通路，后训练上先 RL 出 3 域 × 3 档共**九个专家模型**，再用**多教师 On-Policy 蒸馏(MOPD)**合并成一个——开源权重直接把"预训练规模"和"测试时计算"两条轴同时推到了 frontier 边上。

## 为什么值得读

- **技术报告本身就是综述级的信息量**。架构、scaling law、预训练、后训练、RL 环境、基础设施、部署、安全评测全都给了细节，是少有的"整栈"样本。
- **MOPD 是 On-Policy Distillation 的工业级落地**。我们之前在[《On-Policy Distillation 梳理》](/zh/blog/on-policy-distillation)和 [Seed 自进化 OPD 精读](/zh/reading/seed-self-evolving-opd)里讨论过的 OPD，在这里被用作"九个专家合并成一个模型"的核心手段——这是目前 OPD 最大规模的公开应用之一。
- **自进化任务合成**与 [Skill Self-Play](/zh/papers/insights/2607.22529) 遥相呼应:K3 用持续扩张的层级知识图谱引导 RL 任务合成，和 Skill-SP 的"技能库协同进化"是同一条思路的两种实现。
- 对关心 agentic RL 工程的人，**百万 token 上下文的 RL 基础设施**(partial rollout、KV cache pool、microVM 沙盒)是难得的公开参考。

## 定位:把开源底座拉回 3T 级

报告的动机很明确:开源社区在 test-time scaling 上追得很快，但预训练底座长期停在 1T 参数级，和顶级闭源的差距有扩大风险。K3 的解法是**双轴同时扩**——预训练做到 3T 级开源底座，同时把 RL、推理强度控制、百万 token 长程交互一起推进，最后把完整权重放出来。

直接对标的结果:整体超过 Claude Opus 4.8 / GPT-5.5 / GLM-5.2，落后于 Claude Fable 5 和 GPT-5.6 Sol，但在不少单项上打平甚至反超。

## 架构:三个维度扩信息通路

![Kimi K3 架构三轴:Hybrid Attention(序列)、Attention Residuals(深度)、Stable LatentMoE(宽度)](/images/insights/2607.24653/architecture.png)

报告把架构创新组织成"信息通路"的三个维度:

**序列轴 — Hybrid Attention。** 每个 block 由 3 层 Kimi Delta Attention(KDA)+ 1 层 Gated MLA 组成，backbone 末尾再补 1 层 Gated MLA。KDA 是带通道级遗忘门的 delta 规则递归，这次的关键改进是给 log 衰减加了 scaled sigmoid 下界($g_{\min} = -5$)，数值更稳，而且 chunkwise 计算的对角/非对角块都能用稠密 Tensor Core 矩阵乘，消除了此前线性注意力对角路径的瓶颈。**MLA 层全部用 NoPE**——位置信息完全交给 KDA 的递归门控和衰减来混合，于是 1M 上下文可以**直接外推**，不需要改任何位置编码。

**深度轴 — Attention Residuals(AttnRes)。** 标准残差是"逐层顺序累加"，表示在深层层级容易被稀释;AttnRes 让每一层可以**选择性地读取 embedding 和之前所有层的表示**。为了控制开销，Block AttnRes 把 8 层划为一个 Block、每块只压出单份表示，把内存和通信从 $O(Ld)$ 降到 $O(Nd)$($N$ 为块数)。

**宽度轴 — Stable LatentMoE。** 896 个 routed expert、每 token 激活 16 个(sparsity 56)，三个稳定化手段:RMSNorm 插在 routed 路径上投影前(Normalized LatentMoE);新的 **SiTU-GLU** 激活用 $\beta\tanh(x/\beta)$ 软帽替代 SwiGLU($\beta_1=4$、$\beta_2=25$，输出有界 ≤100);**Quantile Balancing** 按 router 分数的分位数设专家偏置做负载均衡，**完全不用辅助 loss**。

视觉编码器 MoonViT-V2(27 层、约 0.4B)值得一提:它**不从对比预训练初始化，而是从 0 开始用 next-token prediction 训练**，表示直接由语言建模目标塑形，图文/视频共享参数。优化器用 Per-Head Muon，按注意力头分别做正交化。

## 预训练:2.5× scaling 效率 + 四阶段上下文课程

架构、数据、训练改进合计带来约 **2.5× 的整体 scaling 效率**(相对 K2)——这是报告里最重要的数字之一，意味着同样算力下可及的 Loss 水平显著前移。长上下文靠四阶段课程:预训练期 8K→64K,cooldown 期 256K→1M;长文数据上做了真正长且连贯内容的上采样，并把多模态文档、子任务拼接置换来合成超长依赖。

## 后训练:九个专家，一个模型

![Kimi K3 后训练管线:SFT → 3 域 × 3 档 RL → MOPD → 部署友好](/images/insights/2607.24653/posttraining.png)

这是和我们博客主题最贴近的部分。管线四步:

**SFT** 建立基础策略，数据重点扩了复杂 agentic 任务的轨迹(由历代 Kimi 模型合成、验证加人工标注)，统一走 XTML 聊天模板;**QAT(MXFP4 权重 / MXFP8 激活)从这一步就全程贯穿**，为最后的部署精度铺路。

**RL 阶段刻意不训一个模型，而是训九个**:通用任务 / 通用 Agent / 编程 Agent 三个域，各配低 / 高 / max 三档推理强度。几个关键技术点:

- **Extended partial rollout**:只等一小部分轨迹跑完就开始策略优化，缓解长程任务的尾部延迟;配 per-token 正则容忍数据 staleness。
- **逐题 token 预算**:总 token 数超过(按题目规模缩放的)阈值就扣奖励，这样训出低 / 高 / max 三档"用力程度"不同的专家——推理强度不是 prompt 出来的，是 RL 出来的。
- **Agentic GRM**:不可验证的通用任务用锦标赛式组奖励模型，judge 按 rubric 生成 → 打分 → scorepad 的协议走，并对啰嗦做预算惩罚防 reward hacking。

**MOPD(多教师 On-Policy Distillation)把九个专家合并成一个统一模型**，用教师与学生策略之间的 per-token OPD reward 优化。这正是 [OPD 梳理](/zh/blog/on-policy-distillation)里讲的 on-policy 蒸馏范式:学生在自己的分布上采样，教师提供 token 级信号——区别是这里**教师有九个**，学生要学的是它们的并集。相比硬合并(model soup)或离线蒸馏，on-policy 的 token 级信号能保住各专家在其专域的行为模式不互相冲掉。部署侧另外把预训练的 MTP 层微调为 EAGLE-3 风格的 draft model，用 likelihood 类 LK loss 直接优化接受率做投机解码。

**RL 任务从哪来**——报告给了七个来源，最值得注意的是**知识图谱引导的任务合成**:一张由 agent 持续扩张的层级知识图谱引导素材检索与出题，覆盖知识密集和编程域;以及**个人助理任务**:用 Gmail / Notion / Slack 的高仿真 mock 应用构造跨多天的长程任务，涉及上千次工具调用、百万 token 级上下文。加上白盒组合式环境(防过拟合特定 tool schema)、AET 自主执行任务、内核优化和 WebDev 沙盒，构成了一套可规模化的可验证任务供应链。

## 基础设施一瞥

整份报告的 infra 密度很高，挑三条最有记忆点的:**KCP(KDA Context Parallelism)** 把 KDA 状态更新分解为累积转移 + 本地生成状态，跨 rank 用定长 all-gather 做前缀扫描重建;**MoonEP** 用动态冗余专家实现"完美均衡"的专家并行;**AgentENV** 是基于 Firecracker microVM 的沙盒系统，支持 pause/resume/fork/snapshot——RL rollout 效率的关键。推理侧 KDA 循环状态与 MLA KV cache 统一分页管理，前缀缓存感知调度到舰队级。

整体定位:超 Claude Opus 4.8 / GPT-5.5 / GLM-5.2，逊 Claude Fable 5 / GPT-5.6 Sol，第三方 Artificial Analysis Intelligence Index 57.1(580 个模型第 4),WebDev Arena 第一(1678 Elo)。挑些单项:

## 简评

这份报告最值钱的不是某个单点 trick，而是**"整栈协同"的完整样本**:KDA 的数值稳定性改进是为了让 chunkwise 计算吃满 Tensor Core;NoPE 同时服务架构简洁和 1M 外推;QAT 从 SFT 第一天就介入，所以 MXFP4 部署几乎无损;九专家 RL + MOPD 的组合，本质上是承认"一个策略学所有域所有强度"的优化景观太恶劣，先分治再蒸馏——这个配方大概率会被后续开源旗舰复用。

值得追问的两点:一是 MOPD 的细节给得克制(九教师的 reward 怎么组合、能力冲突怎么解，报告只到 per-token OPD reward 一层)，想复现还得等社区拆解;二是"双轴扩展"的效率账——2.5× scaling 效率相对 K2 很可观，但 3T 级模型的推理成本依然是硬约束，K3 的答案(1M 上下文 + MXFP4 + 投机解码)能否撑住大规模 C 端流量，要看后续的实际部署数据。

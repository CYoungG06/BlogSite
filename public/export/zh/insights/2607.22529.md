# Skill Self-Play:让出题者、解题者与技能库一起进化

> 2026-07-27

## 一句话版本

Skill-SP 把"技能库"变成了自博弈(self-play)的**训练期接口**:Proposer 在动态采样的技能引导下合成"中等难度"的可验证任务，Solver 在这些任务上用 GRPO 训练，技能控制器再根据执行反馈精炼、剪枝、归纳技能——三个角色协同进化，既保住了开放式任务的多样性，又保住了奖励信号的可验证性。

## 为什么值得读

- **自进化是当下后训练最密集的主线之一**(Absolute Zero、SPIRAL、SDPO……)，这篇 Qwen 大模型应用团队主导的工作给出了其中迄今最结构化的一种解法;
- **与我们精读过的 [Seed](/zh/reading/seed-self-evolving-opd) 正好互补**:Seed 从轨迹里"提取技能"服务蒸馏，Skill-SP 把技能当"出题脚手架"服务课程生成——"技能"这个概念正在从推理时的工程组件，变成训练期的基础设施;
- 方法本身不难懂，但工程设计密度很高(双流生成、有效性门、技能库生命周期)，值得拆开看看每个零件各赚多少分。

## 要解决的问题:多样性与可验证性的两难

LLM 自进化(self-evolution)的核心循环是"自己出题、自己解题、自己评分"。现有方法卡在一个根本张力上:

- **环境绑定型**(Absolute Zero 之于代码、SPIRAL/MARSHAL 之于游戏、Search Self-play 之于检索):把任务生成锚定在专门的外部环境里(执行器、模拟器、检索引擎)，验证精确可靠——但学习被锁死在狭窄、预定义的操作域里，泛化不到开放场景;
- **开放式自生成型**:不加环境约束地让模型自己出题，再做事后过滤(格式检查、多数投票)——任务面宽了，但质量失控:病态题、模板题泛滥，误差逐轮累积导致合成数据坍缩(synthetic data collapse)。事后过滤只是**被动拒收**明显的坏题，无法主动引导出题者产出多样、合法、可复用的任务模式。

本文的破题点是 **agent skill(智能体技能)**:一个技能是把特定场景的操作规程、资源与验证方式打包成的可复用模块。**单个技能保证特定场景内的深度可验证执行;技能之间的动态路由则维持开放式的任务多样性**。此前技能相关工作多把它当推理时接口(检索、压缩、渐进披露)，本文的关键转向是把它用作**训练期的任务合成接口**——让技能库随自博弈课程共同进化。

## 核心机制

### 任务形式:提示 + 验证契约

一个可验证任务记为二元组 $(x, c)$:$x$ 是给 Solver 的任务提示，$c$ 是**隐藏的机器可读验证契约**(比如期望的工具调用序列、谜题的唯一解)。环境据此给出奖励 $R_{\mathrm{solve}}(x, y, c)$,Solver 在该任务上的期望成功率记为 $v_{\mathrm{solve}}$。

### 协同进化循环

![Skill-SP 协同进化循环:技能库、Proposer、Solver 与技能控制器](/images/insights/2607.22529/framework.png)

**Proposer:在技能引导下出"中等难度"的题。** 每轮从技能库动态采样技能 $s \sim S$(按使用统计 $\sigma$ 权衡高产技能的利用与生疏技能的探索)，然后双流出题:

- **技能流**:$(x, c) \sim \pi_{\mathrm{propose}}(\cdot \mid s)$，技能提供强结构先验与生成提示;
- **探索流**:$(x, c) \sim \pi_{\mathrm{propose}}(\cdot \mid \varnothing)$，无技能约束，负责开拓新任务空间、防止模式坍缩。

Proposer 的奖励设计得很讲究:

$$R_{\mathrm{propose}} = \big(1 - 2\,|\,v_{\mathrm{solve}} - 0.5\,\big|\big) \times \mathbb{1}\{(x, c) \text{ 有效}\}$$

前一项是**中等难度分**:Solver 成功率 0.5 的任务(学习前沿)得分最高，太易或太难都不得分;后一项是**有效性门**:技能流的题必须通过 schema 合规、技能自带验证器 $\nu$、以及"probe 一致性"(当前 Solver 采 $K$ 次，多数答案唯一且与契约 $c$ 吻合)三重检查，否则直接零分——这就堵死了"出病态题骗取难度分"的 reward hacking 通道。$v_{\mathrm{solve}}$ 由当前 Solver 实测估计，所以难度标签始终贴着 Solver 的最新水平走。Proposer 用 GRPO 更新。

**Solver:在动态课程上训练。** 两流的有效候选题按 $R_{\mathrm{propose}}$ 排名，按混合比 $\alpha$ 取 top-M 组成当期训练池 $D^{(t)}$,Solver 在其上以 GRPO 最大化环境验证奖励 $R_{\mathrm{solve}}$。

**技能库:完整的生命周期管理。** 这是本文区别于"静态技能库"工作的关键:

- **精炼(refine)**:跟踪每个被采样技能的统计 $\sigma$，分析无效生成尝试、诊断系统性失败模式，修订技能内容;
- **剪枝(prune)**:持续只产简单题(期望前沿奖励低于 $\gamma_{\mathrm{prune}}$)的过时技能归档退役，节省生成预算;
- **归纳(induce)**:探索流中达到前沿奖励阈值 $\gamma_{\mathrm{induce}}$ 的新颖候选题，由技能控制器 $\pi_{\mathrm{control}}$ 抽象成候选技能包，经结构完整性检查与语义查重后入库:

$$S^{(t+1)} = \big(S^{(t)} \setminus S^{(t)}_{\mathrm{prune}}\big) \cup S^{(t)}_{\mathrm{new}}$$

也就是说，**开放式探索的成功经验被不断蒸馏回结构化的技能库**——探索流负责"开荒"，技能库负责"建制"。

## 实验要点

设置:5 个 3B–14B 开源底座(Qwen3-4B-Instruct、Qwen3-8B、Ministral-3-8B/14B、Granite-4.1-3B),Proposer 与 Solver 同权重初始化;评测两类可验证任务——工具调用(API-Bank L1–3、BFCL 四个类别)与逻辑推理(ZebraLogic 约束满足网格谜题，四种规模);统一训练 5 轮迭代。

**工具调用(论文 Table 1)**

- 五个底座**全部提升**:Qwen3-4B-Ins 平均 +6.5 个百分点;初始严重未对齐的 Ministral-3-8B 整体 +42.9，堪称"救援式"翻盘;
- 对照组 Unguided SP(无技能引导、只有事后过滤)增益一致更小，部分子任务甚至倒退——它常常造不出合法任务，学习循环被"饿死"。

**逻辑推理(论文 Table 2)**

- 五个底座整体准确率全部提升;逻辑上初始未对齐的 Ministral-3-14B 整体 +12.0，小规模谜题上超过 +35;
- Unguided SP 在推理域**根本无法自举**(合成不出合法谜题)，凸显主动结构引导的必要性;
- 但极限难度(Large/X-Large)对初始弱模型仍进展有限——纯自博弈需要最低能力门槛才能启动有效学习信号。

**数据循环诊断(Figure 5–6)**:技能流产出任务的难度 $v_{\mathrm{solve}} \approx 0.57$，显著比 Unguided SP(0.70)与探索流(0.75)更贴近 0.5 的学习前沿;技能库每轮归纳约 20 个新技能包，5 轮后活跃技能达 86 个、有效技能(香农熵度量)稳步增至 46 个——课程没有坍缩到少数主导模式上。

## 简评

**亮点**:用"技能"这个恰到好处的中间层化解了自进化的核心两难;有效性门是简洁而必要的防 hacking 设计;技能库的全生命周期管理(尤其"探索流蒸馏新技能"的归纳通道)让系统具备真正的开放性;对初始弱/未对齐模型的"救援效应"实用价值很高——不是每个团队都能从强对齐的底座出发。

**局限**:实验只跑 5 轮、最大 14B，更长程的协同进化是否稳定(技能库会不会漂移或臃肿)未验证;整套方法依赖机器可读的验证契约 $c$，天然限于可验证任务域，开放式对话、写作类任务不适用;极限难度任务的自举仍需能力门槛;技能库跨模型、跨域迁移的效果是开放的。

**和我们最近读的东西的关系**:Skill-SP 回答"题从哪来",OPD/OPSD 回答"答案怎么学"。前者用技能引导课程生成，后者用(特权)教师提供逐 token 密集监督——两者组合(技能课程 + on-policy 蒸馏)是很自然的下一步。另外它的"探索流蒸馏回技能库"，和 Seed 从成功轨迹提取技能再注入上下文，本质上共享同一个直觉:**把一次性的成功，固化成可复用的结构先验**。

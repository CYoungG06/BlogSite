上次开源的 [GCodey](/zh/blog/gcodey-agent-harness/) 是给 agent 用的 harness，这次开源的东西是给人用的。

[共读(Codex-Co-Read)](https://github.com/CYoungG06/Codex-Co-Read)，一个本地运行的论文阅读器，今天刚推到 GitHub，MIT。界面一句话能讲完，左边是原版 PDF，右边是对话框，坐在对面陪你读论文的是 Codex。

![共读的主界面。左侧是原版 PDF 的连续页流，右侧是对话面板，底部可以选模型、思考深度和三档介入深度。](/images/blog/codex-co-read/reader-main.png)

## 为什么做

起因很私人。我已经很难像读书时那样，把一篇论文从头到尾啃完了。AI 读论文的工具试过不少，它们大多太热情。你问一句这个公式怎么来的，它回你一份全文综述，五个要点，外加未来工作展望。你还没读到的地方，它先替你剧透了。注意力没有省下来，思路还被打断。

后来我们想明白，难点在交互上。模型读懂论文已经不稀奇，稀奇的是分寸，Agent 手里可以有全文，它此刻应该说多少、说到多深，得由读者说了算。这个思路我们叫共同注意力。模型掌握更大的背景，人的视线落在哪里，回答就贴到哪里。

共读把「Codex 能知道多少」和「此刻应该说多少」拆成了两件事。

- 全文的身份是背景。打开论文时，PDF 能提取的文字会带着明确的页码边界交给 Codex，并且标记为不可信内容，防止论文里的句子被当成指令执行。它知道全文，默认只回应你眼前的那一处。
- 介入深度有三档，点答、讲清、发散。它和模型、思考深度是三个互相独立的旋钮，各司其职。
- 发送即快照。按下发送的那一刻，当前页码、页面文字、选区、模型、思考深度、模式和附带的图片全部冻结。等回答的时候随便翻页，正在执行的那一轮不会被偷偷改变。想把刚翻到的页面补进这一轮，有专门的按钮。
- 页面图像有三档，关、自动、开。自动档会在问题涉及图、表、公式，或者页面几乎提取不到文字时，自己附上当前页的截图。
- 同一篇论文可以开多个会话，各自记住自己的 thread、消息、页码、滚动位置、缩放和模型设置。精读一遍，泛读一遍，互不打扰。重新打开应用，会回到你最近用的那个会话。

还有一处语义值得单独说。停止只是中断生成，已经说出口的话留在了 thread 里，收不回来。所以修改上一轮提问用的是分叉，从被替换的问题之前切出一条新 thread，输错的字不会进入新分支的上下文，旧 thread 完整保留，随时可以回去看。

## 两种模式，一条链路

应用分共读和研究两种模式。共读模式下 Codex 不调用任何工具，跑在只读、无网络的沙箱里，审批请求一律自动拒绝，它就是个纯粹的讨论对象。研究模式把 agent 能力放开，写入范围锁在 research-workspace 目录，联网和越权操作逐项审批，超时自动拒绝。

链路也值得讲。浏览器界面，本地 Express/WebSocket 桥接层，codex app-server，你的 ChatGPT 账户，一共四站。全程没有 API key。本地 Node 服务通过 stdio 拉起 codex app-server，模型列表和思考深度直接读你账户里可用的那一份。Codex CLI 如果用 ChatGPT 登录过，打开应用就能用，不用再配任何东西。目前只在 codex-cli 0.146.0 上做过兼容验证，升级后遇到怪问题，可以先跑 npm run doctor 查本机环境。

## 四十三小时的开发过程

这个项目几乎完全是在和 Codex 的对话里长出来的。会话拉了四十三小时，中间压缩了四次上下文。

前四十轮一行代码都没写。先把共同注意力拆成三层视野，聚光区、周边区、全局地图，再定下三档介入策略，然后画了一张可点击的界面草图。想清楚了才动手。

第一版其实做成了 ChatGPT 插件，能跑，论文解析出十三个章节。我看完的反应很直接，效果一般，我要的是一半原版 PDF 一半对话。Codex 的判断也干脆，不在插件的小组件里硬改了，推翻，做成独立的本地应用。现在回头看，那次推翻是整个项目最值的一次决定。

之后是漫长的打磨，PDF 渲染的坑基本踩了个遍。缩放时新画布还没画完就藏起旧画布，屏幕闪白帧，修成旧帧活到新帧完成。二十二页同时重绘，卡，改成只给当前页前后两页挂高清画布。高分屏下发虚，按 devicePixelRatio 重渲染才好。还有一次 Codex 网络短暂重连，界面把重试报成了失败，改成静默等待，只在真正失败时提示。中文输入法候选词没确认时按 Enter 会误发送，这个修完直接写进了 README 的亮点清单。

开源前夜审出两个 P0。仓库里内置的示例论文 PDF 只有 arXiv 的非独占分发许可，不能跟着仓库再分发，撤掉，默认示例改成运行时从 arXiv 加载 Attention Is All You Need。本地 WebSocket 没有来源校验，恶意网页理论上能跨站连上你本机的 agent，修掉，强制只听 127.0.0.1。这两个洞堵上，才敢推。推送之后，发布前启动的那轮会话与持久化审计也跑完了，当晚合入一版会话生命周期加固。断线后问题到底送没送达，浏览器存储不可用时怎样降级，重新打开应用该恢复哪个会话，这些平时看不见的边角，都补上了明确的语义和测试。

UI 的后期是接力完成的。Codex 搭完主体，我自己上手改过一版，之后又在另一个会话里和 Kimi 磨了一轮，自研了下拉组件，补上中英切换，收紧顶栏，给菜单和抽屉加动效。一个项目，两个 agent，再加一个打杂的人。

## 边界

这是独立开发的非官方项目，和 OpenAI、alphaXiv、arXiv 都没有隶属关系。灵感上受 alphaXiv 论文中心式阅读体验的启发，很认同把原文和讨论放在同一个界面的方向，代码是独立实现，没有用它家的代码和素材。目前没有 OCR，扫描件和纯图片页面提取不到文字。共读模式的沙箱约束的是已知路径，对隔离有更高要求的话，建议用独立系统用户或容器来跑。应用按本地回环地址设计，别把端口暴露到公网。

如果你也有一个躺着的 ChatGPT 订阅，和一堆读不完的论文，欢迎试试。仓库在 [github.com/CYoungG06/Codex-Co-Read](https://github.com/CYoungG06/Codex-Co-Read)，README 有中英双语，三个平台都有一键启动脚本。

读论文这件事，AI 可以陪着，注意力得是你自己的。

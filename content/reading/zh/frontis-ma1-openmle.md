## 摘要

递归自我改进(RSI)要求 AI 系统能够改进「构建 AI」这一过程本身(即 AI4AI);机器学习工程(MLE)为研究这种能力提供了一个具体、可执行的试验场。作者提出 **OpenMLE**:一个面向 MLE 领域 RSI 研究的开放全栈系统,涵盖带执行反馈的可验证任务环境(OpenMLE-Gym)、算子学习(OpenMLE-RL)与长时程搜索(OpenMLE-Evo)。在这套栈上,他们把 Frontis-MA1(35B)后训练为面向 MLE 的**元进化 agent(meta-evolution agent)**,让后训练与推理围绕四个原子程序进化算子(Draft、Improve、Debug、Crossover)对齐:同一组算子先通过执行 grounded 的 SFT 与 RL 训练(训练数据对全部评测 benchmark 去重),再在推理时被组合成长时程搜索,把学习与进化耦进同一个回路。在 MLE-Bench Lite 上、每任务 12 小时、单张 RTX 4090(12GB 显存)的预算下,Frontis-MA1(35B)配 OpenMLE-Evo 把 Medal Average 从 39.39% 提到 60.61%;配 OpenMLE-Evo-Max(与 benchmark 无关的经验先验 + 异步搜索)达到 71.21%,超过 GPT-5.5 + Codex,接近 GPT-5.6 Sol 与 2.8T 的 Kimi K3。在 held-out 的 NatureBench Lite 上,两个组件都能迁移:固定框架换入训练后的模型,Match-SOTA 从 50% 升到 70%;固定模型换入 OpenMLE-Evo,从 20% 升到 50%。

## 1 引言

AI 能力的增长不再只由人类工程师推动:越来越多的 AI 系统自己写代码、跑实验、搜索设计、帮助构建下一代 AI 系统。这个更大的方向常被称为 **AI for AI(AI4AI)**——用 AI 系统来构建和改进 AI;而它更宏大的终点是**递归自我改进(RSI)**:每个被改进的系统反过来进一步改进产生其后继的过程。要到达这个终点,需要的不仅是更强的单轮生成或规划,而是能做「AI 训练 AI」和自动研究的 agent:检查数据、提出算法、执行实验、诊断失败、并决定下一单位算力花在哪里。

**机器学习工程(MLE)**是 AI4AI 一个特别直接的实例:agent 必须为真实任务构建 ML 方案,并通过执行反馈迭代改进它。一条典型轨迹从一个能跑的 pipeline 开始,经过反复实验,逐步逼近可与强人类或前沿模型竞争的方案。每次迭代都消耗时间和算力,结果可能要几分钟甚至几小时后才知道——这使 MLE 成为研究「agent 如何在延迟、带噪、异质的反馈下改进 AI 系统」的具体而苛刻的试验场。

![图 1:本工作的定位。左:在 AI4AI 内部,MLE 是本文的任务域;OpenMLE 栈训练并部署 Frontis-MA1,它既是栈的产物、也是栈的引擎,只在第三方 benchmark 上评测。右:从进化到 RSI 的机制阶梯——元进化回路(橙色)处在「改进者本身被训练」这一级,Frontis-MA1(Meta-evolution Agent)正是以此命名。](/images/reading/frontis-ma1/fig2-positioning.png)

先前工作沿三条互补但重叠的路线推进 MLE agent:其一是基于结构化或进化搜索的**推理时 harness**;其二是**可执行任务与环境**的构建;其三是以执行反馈**后训练** MLE agent。也有系统横跨其中两条(如 MLE-Dojo 支持模型调优、AceGRPO 把迭代执行轨迹回收进训练),但在作者审计的代表性公开系统中,没有一个同时覆盖:可扩展的任务与环境构建、执行 grounded 的 agent 后训练、以及把训练出的 agent 部署进长时程搜索的进化 harness——再加上复现整个回路所需的全部产物。

OpenMLE 就是为此提出的开放全栈方案:

- **OpenMLE-Gym**:构建 5,758 个质量门控的可执行任务,提供隔离执行、结构化反馈与任务专属评测;
- **OpenMLE-ERL**:用预算自适应的监督微调与强化学习,把已验证的解法与修订变成更强的 MLE 行为;
- **OpenMLE-Evo**:围绕结构化经验、按质量/进展/新颖度做非贪心选择、以及算子条件化记忆,组织长时程搜索。

Draft、Improve、Debug、Crossover 这四个算子是后训练与推理之间共享的接口:已验证的进化转移为训练提供监督,训练的正是搜索后来组合的那些变换——训练出的模型因此成为进化 harness 的**变异引擎**,形成图 1 所示的元进化回路。以这种方式训练并部署的模型,称为**元进化 agent**。

主要结果(均在 MLE-Bench Lite、每任务固定 12 GPU 小时预算下):模型层面,同一 OpenMLE-Evo harness 下,Frontis-MA1-35B 相对 Qwen3.6-35B-A3B 基座把 Medal Average 从 39.39% 提到 60.61%,Human Rank 从 0.5828 提到 0.7647;harness 层面,配对比较显示 OpenMLE-Evo 在四个前沿模型上都优于通用 Claude Code / Codex 支架,也优于原版 AIRA-Evo;系统层面,Frontis-MA1-35B + OpenMLE-Evo-Max 达到 71.21% Medal Average 与 0.8126 Human Rank,超过 GPT-5.5 + Codex。作为受控跨模型复现,Frontis-MA1-30B 在同一 harness 下从 34.85% 提到 53.03%。NatureBench Lite 的受控比较则表明,执行 grounded 的后训练与适配后的进化搜索都能迁移到竞赛式 MLE 之外。

## 2 问题形式化

**从 AI4AI 到元进化。** AI4AI 描述优化的*对象*:AI 系统参与创建或改进其他 AI 系统(训练代码、模型架构、算法、agent harness、AI 硬件)。进化(evolution)描述优化的*过程*:AI 根据执行反馈反复修改候选系统。**元进化(meta-evolution)**再闭合一圈学习回路:把这些进化轨迹复用起来,训练那个提出未来变换的模型。RSI 则要求更强、可持续的回路:每个升级后的系统都进一步改进产生其后继的过程。OpenMLE 研究的是从进化走向元进化的具体一步:可执行的搜索经验经由 SFT 与 RL 回流,改进程序变换模型。

**可执行的进化。** 沿用 MLE-Dojo 与 MLE-Bench 的设定:每个任务 $\tau$ 包含自然语言规格说明、可见数据资产、提交契约、任务专属评测器与沙盒执行环境。在第 $t$ 步,推理时搜索算法选择算子 $a_t$,并由零个或多个父代程序及其执行反馈构造算子上下文 $c_t$;模型随后提出候选程序:

$$p_t \sim g_\theta(\cdot \mid \tau, a_t, c_t), \qquad s_t = R_\tau\big(\mathcal{E}(p_t, \tau)\big)$$

其中 $g_\theta$ 是以算子为条件的程序生成策略;沙盒 $\mathcal{E}$ 执行 $p_t$,任务专属评测器 $R_\tau$ 把执行结果映射为任务分数 $s_t$,连同状态、日志、产物与运行时元数据一起返回。由于各任务指标量纲与方向不一,后文会把 $s_t$ 先转成「越大越好」的有符号分数 $\tilde{s}_t$,再归一化为奖励。

每个程序及其执行反馈都存入任务本地的程序数据库,变换算子被反复施加以产生新候选。在有限执行预算内,进化推理的目标是找到有符号分数最高的候选:

$$p^\star = \underset{t \in \mathcal{I}}{\arg\max}\; \tilde{s}_t$$

$\mathcal{I}$ 是预算内搜索记录的全部候选索引集。OpenMLE 把算子空间实例化为 Draft、Improve、Debug、Crossover,而把它们的全局组合留给推理时搜索算法。

**从可执行经验中学习进化。** 元进化要改进 $\theta$,使 $g_\theta(\cdot \mid \tau, a, c)$ 给执行结果更好的程序分配更高概率。SFT 与 RL 都可以写成优化:

$$\mathcal{L}_{\text{evo}}(\theta) = -\,\mathbb{E}_{(\tau_i, a_i, c_i, p_i)}\Big[ w(s_i) \log g_\theta\big(p_i \mid \tau_i, a_i, c_i\big) \Big]$$

其中 $s_i = R_{\tau_i}(\mathcal{E}(p_i, \tau_i))$ 是执行分数,$w(s_i)$ 把这个结果转成学习权重。SFT 阶段,质量过滤保留高分程序并赋予正监督;RL 阶段,新采样的程序按处理后的执行奖励与熵优势加权,进入裁剪策略目标。两个阶段更新同一组参数 $\theta$,让高质量可执行程序在 $g_\theta$ 下更可能。

> **译注**:这个形式化把「搜索」与「训练」写进了同一个目标:搜索负责产生带执行分数的 $(\tau, a, c, p)$ 四元组,训练负责让这些四元组里高分的更可能再次出现。和我们精读过的 Seed(OPD)对照看很有意思——Seed 是「轨迹内」让模型当自己的事后分析师;这里是「轨迹间」让整个搜索历史当训练素材,粒度从 token 级换成了算子级,但「改进者自身被改进」的精神一脉相承。

## 3 OpenMLE-Gym:可扩展的可验证环境

> **要点**:MLE 需要一个有算力背书、可验证的 gym。环境必须能承载大型资源密集型任务、在受控预算下执行候选程序、用任务专属评测器返回可复现的诊断与奖励。gym 的规模化靠自动化任务构建:从策展锚点、Kaggle 数据集与 Kaggle 竞赛三条路径产出 5,758 个质量门控的可执行环境,覆盖八种模态与六类核心任务。

### 3.1 环境契约

每个 OpenMLE-Gym 任务都是由五要素定义的环境实例:**任务/状态**(任务规格、公开数据、隐藏评测器、资源预算、当前工作区状态);**动作**(agent 提交的 MLE 程序及其执行需求);**转移**(沙盒执行:具现化工作区、对公开数据运行程序、产出有效提交时调用评测器);**观测**(结构化记录:执行状态、任务分数、日志、错误类型、生成的产物、运行时元数据);**奖励**(评测器返回的可验证任务分数)。任务完成、控制器停止条件、时间或算力预算共同决定交互是终止还是截断。

### 3.2 可扩展的任务构建

三条来源路径在质量—规模权衡上互补:

- **策展锚点(Curated Anchors,156 个)**:从已有论文与 benchmark 人工精选,质量最高但规模受限;直接下载原始资产加工成可执行包。
- **Kaggle 数据集(3,362 个)**:沿用并扩展 MLE-Smith 的数据集→任务管线,自动诱导的目标质量参差,因此再加包级质量控制。
- **Kaggle 竞赛(2,240 个)**:人类撰写的问题描述、评测指标与提交协议提供更强的任务 grounding,参赛历史与排行榜记录还提供「任务支持有意义、可比较评测」的外部证据;Meta Kaggle 目录支持规模化采集。自建爬取与竞赛构建管线,并**剔除与 MLE-Bench 重叠的竞赛**以保证评测完整性。

![图 2:OpenMLE-Gym 的任务策展与可执行格式。左:来源层级(质量与规模的权衡);中:Kaggle 竞赛从 Meta Kaggle 目录(~11,000)经资格筛选(3,972,保留 36%)、可执行打包(2,839,保留 26%)到质量门控(2,240,保留 20%)的漏斗;右:统一任务包格式——公开输入、私有答案与可执行工具。](/images/reading/frontis-ma1/fig3-gym-curation.png)

所有来源被映射到统一的可执行任务包:原始资产放 `raw/`;agent 可见的描述、训练数据、测试输入与示例提交放 `data/public/`;隐藏答案隔离在 `data/private/`;任务专属的 `metric.py` 校验预测文件并返回标量执行反馈。竞赛分支的自动化框架把竞赛 slug 转成标准化包:下载并盘点文件,结合本地证据(schema、数据类型、维度、采样行)与 Meta Kaggle 记录生成任务描述与 `prepare.py`(确定性地切分标注数据、隔离公开输入与私有答案、生成 schema 兼容的示例提交),再生成 `metric.py` 并通过执行准备代码与给示例提交打分来验证整个包;失败与断言错误作为反馈进入有限次重试,仍不可构建或无法产出有效标量指标的包在语义质量过滤之前就被移除。

### 3.3 任务质量过滤

构建之外还有一道基于 LLM 的质量过滤器:对每个任务包联合检查任务描述、原始文件、处理脚本、处理产物、代表性数据样本,沿五个维度给出结构化判断——**任务有效性、数据充分性、原始数据利用率、任务复杂度、数据质量**。这些标准共同识别:可被平凡规则解决的退化目标、训练或评测信号不足、对源资产的表面化使用、难度错配、数据泄漏、标注错误与畸形处理。只有指标有效且获得「严格推荐」结论的任务才被保留——语义质量评估与构建期的可执行性检查由此分离。

### 3.4 规模化沙盒执行

契约由共享沙盒执行后端落地:中心化调度器接收 API 请求、记录任务、追踪 worker 可用性,按资源需求把请求分发给 CPU/GPU Docker worker;每个 worker 具现化隔离的任务工作区,挂载任务数据与评测器,执行候选程序,并把日志、提交、输出与产物写回共享存储。控制、执行、存储分离,支撑长时间 MLE 作业的可复现打分与可扩展并行。

后端返回**六种反馈模式**:成功完成、运行时错误、缺代码、缺提交、打分失败、超时。每条记录保留触发条件连同状态、分数(如有)、日志、错误类型、运行时元数据与工作区产物,让 agent 能把「无效执行」与「任务表现差」区分开。

> **译注**:这六种反馈模式看似工程细节,实则是 RL 数据质量的前提——SWE-1.7 那篇蒸馏里 Cognition 也反复强调 verifier 的假阳性/假阴性问题。可执行 RL 的共同教训:奖励信号的「干净」比「多」重要得多。

### 3.5 组成与统计

OpenMLE-Gym 共 5,758 个可执行任务:156 策展锚点 + 3,362 Kaggle 数据集任务 + 2,240 竞赛任务。跨来源覆盖表格、文本、时间序列、图像等模态;规范化标签后 11% 为多模态,分类与回归合计 87%。作为对比,此前可执行任务资源的规模为:MLE-Smith 606、MLE-Dojo 200+、MLE-Bench 75、MLGym-Bench 13、MLAgentBench 13。(因源数据许可限制,1,415 个任务释出完整数据包,其余 4,343 个只释出 `prepare.py` 与 `metric.py`,不再分发源数据。)

## 4 OpenMLE-ERL:强化可复用的进化算子

> **要点**:RSI 训练应该改进「模型在固定预算内能找到的最好解」。执行 grounded 的 SFT 让重复采样下强解与有用修订变多;RL 用自适应分数界与熵优势奖励「候选质量」而非仅仅「有效性」。验证成本必须塑造数据收集与训练:预算自适应 SFT 达到配额或执行上限即停,把预算留给成功稀疏的任务;异步 RL 让已完成的「生成—执行」组立即进入训练,不等最慢的作业。进化搜索依赖的是「修订」而非只有「新草稿」,因此四个算子都从轨迹转移中训练;有状态 RL 用奖励、子代奖励方差与访问冷却来选择父代。

**动机。** 进化式自动研究的评判标准是**有限搜索预算内找到的最好可执行程序**。控制器可能调用 Draft / Debug / Improve / Crossover 成百上千次,所以模型要学的远不止单轮解题:它必须在搜索展开的过程中反复修复、精炼、重组程序。后训练因此应当扩大「重复采样可达的强程序集合」,同时改进推理 harness 组合的那些单个变换。

SFT 与 RL 在这个目标下分工互补:执行 grounded 的 SFT 从更强的教师那里蒸馏完整解法与成功的局部修订,在在线学习开始前给模型更广的可执行行为集合;RL 随后在这个被拓宽的分布内,把概率质量推向更好的候选。这个分工的动机来自 RLVR 的已有分析:RL 能通过强化已有奖励的解来提升 Pass@1,但在大 $K$ 下收益有限,而教师蒸馏能引入基座模型采样支撑集中不存在的行为。

可执行的进化训练也不同于数学与代码生成上的短程 RLVR:很多程序根本产不出可用奖励;成功的程序拿到的是不同指标、不同量纲的连续任务分数;反馈要等几分钟到几小时的沙盒运行;而且每个非 Draft 动作都依赖于为扩展选中的父代程序。

### 4.1 可训练的原子算子

OpenMLE 的一个核心设计原则是:**把模型学到的局部技能与推理时使用的搜索算法分开**。不训练完整轨迹,而是训练一小组作用在可执行候选上的、可复用的程序变换算子。这避免了稀疏的、特定于控制器的监督,也让同一组学到的算子能被不同的进化搜索过程在共享沙盒协议下组合。算子词表(Draft、Improve、Debug、Crossover)沿用 AIRA 式可执行 MLE 搜索与 AIDE 式代码空间探索,但 OpenMLE 把它们改造为显式的 SFT 与 RL 目标。

### 4.2 执行 Grounded 的监督热启动

**预算自适应收集。** 每个任务在沙盒中执行采样程序,按有效性与任务分数保留样本;达到接受样本配额、或任务耗尽执行预算,收集即停——简单任务提前结束,把更多尝试留给成功稀疏的任务。这种难度感知的拒绝策略(DART-Math 的思路)把验证算力导向「继续探索仍能找回有用监督」的任务。

**并行与进化两条采样路径。** 并行路径独立采样并执行完整的 Draft 解,贡献 17,245 条完整响应样本;进化路径在已执行的程序上施加 Improve、Debug、Crossover,从高质量局部轨迹段中保留有用步骤,贡献 9,014 条轨迹步样本。两条路径合起来构成随 OpenMLE 发布的 **26,259 条 SFT 语料**。进化路径里有个细节:一个有效终点往往要经历多次 Debug 才出现,此时回溯到之前那个非 Debug 算子,用 LLM 从这段修复轨迹中筛出值得保留的步骤。

### 4.3 执行 Grounded 的强化学习

![图 4:从已执行的 rollout 中学习。上:SFT 语料构建的两条路径(并行路径保留过阈值的 Draft;进化路径从 Debug 修复链中回溯筛选),在预算自适应停止规则下形成 26,259 条样本。下:RL 对选定算子按「父代奖励 + 子代奖励方差 + 访问冷却」选父代;Top-1/Top-K 自适应界把当前 rollout 组的原始分数重映射为处理奖励,低于下界的截断为 0;熵优势进一步放大上尾学习信号。](/images/reading/frontis-ma1/fig7-rollouts.png)

**让异质结果可比。** 一个任务优化 accuracy、另一个优化 log loss,即使对齐了方向,原始分数区间也不可比。设 $\tilde{s}$ 为转成「越大越好」的原始分数,先用一对固定任务界定义有界基础奖励:

$$r_{\text{base}}(\tilde{s};\, b_{\text{best}}, b_{\text{worst}}) = \mathrm{clip}\left(\frac{\tilde{s} - b_{\text{worst}}}{b_{\text{best}} - b_{\text{worst}}},\ 0,\ 1\right)^{\alpha}, \quad \alpha > 0$$

固定界提供了共同区间,但排行榜或理论极值往往远比当前策略实际到达的分数区域宽——这时,明明有差别的程序会坍缩成几乎相同的奖励。OpenMLE 因此从每个任务的**历史 on-policy 分数前沿**导出自适应界,把 $\tilde{s}$ 重映射为处理奖励 $r_{\text{proc}}$。界随策略演化,在当前候选实际所在的区域保留分辨力,同时维持稳定的奖励方向。这与自适应可验证环境和 evolving-rubric 训练的共同教训一致:评测器的刻度必须保住有判别力的 on-policy 反馈。

**把学习信号集中到上尾。** 分数可比之后,剩下的问题是每个候选应该以多大强度影响更新。MLE 的评测奖励的是「找到的最好程序」的质量,一个勉强能提交的样本不应拿到和最优样本相同的正奖励。OpenMLE 使用**熵优势(entropic advantage)**,放大每个 rollout 组内靠近顶部的奖励差距(沿用 TTT-Discover 的上尾原则与 Best-of-$N$/Pass@$k$ 目标)。省略实现中用于稳定化的最大值居中,变换为:

$$A^{\text{ent}}_i \approx \frac{\exp(\beta\, r_{\text{proc},i})}{\frac{1}{G-1}\sum_{j \neq i}\exp(\beta\, r_{\text{proc},j})} - 1$$

$\beta$ 控制集中度,在固定的熵/KL 预算下选取。这些优势替代了 GRPO 式组归一化信号,进入裁剪策略目标。自适应界先让组内差异「看得见」,熵加权再把显著更多的学习信号导向最好的候选,而不是均匀强化所有「没失败」的程序。实测效果:组内最佳候选的平均处理优势从 1.58 提升到 6.39(**上尾信号增强 4.0 倍**);组合自适应界与熵加权后,Group Best Reward 的平滑峰值提升 +0.089(早期简易 harness 下 test medal rate 从 24.2±5.7 到 34.8±4.3)。

> **译注**:这个熵优势可以直观理解为「softmax 化的组内竞争」——普通 GRPO 用 z-score 归一化,优劣差距是线性的;这里换成 exp 加权比值,头部候选的优势随 $\beta$ 指数放大。和 SWE-1.7 的 top-p 回放放一起看:一个管「别让低质量样本污染梯度」,一个管「让最好的样本主导梯度」,都是让 RL 的梯度信号对准真正值得学的 token/轨迹。

**异步 rollout 消除拖尾。** 与 token 级验证不同,MLE RL 的主要延迟来自执行候选程序,而不同任务、不同解法的运行时长差异巨大。同步 batch 里,已完成的组要空等最慢的沙盒作业返回。OpenMLE 改为独立启动各「生成—执行」组,trainer 从队列中消费已完成的组——把策略更新与名义 batch 中最慢的作业解耦,同时保留组级优势。

**为算子学习选择有信息量的状态。** 进化 RL 不仅要选任务、选算子,还要选算子作用的程序状态。均匀采样会把更新花在已耗尽或无信息的区域;贪心采样则反复在现任最优上训练、压制多样性。选定要练习的算子后,OpenMLE 按适应度比例效用采样父代,效用由三项组成:

$$F(p) = \mathrm{norm}(R_p) + \mathrm{norm}\Big(\underset{c \in \mathrm{child}(p)}{\mathrm{Var}} R_c\Big) + \mathrm{norm}(C_p)$$

$R_p$ 偏好强父代;子代奖励方差 $\mathrm{Var}_{c \in \mathrm{child}(p)} R_c$ 识别「算子效果仍有信息量」的区域;$C_p$ 是随重复访问递减的冷却系数。第一项利用有前景的解,第二项瞄准学习信号未解决的状态,第三项防止单个 incumbent 垄断 rollout 预算。

## 5 OpenMLE-Evo:扩展经验驱动的长时程搜索

> **要点**:当搜索能从经验中学习,测试时扩展就变成了**测试时学习**。对 AI4AI 与 RSI 而言,只生成更多候选不够——搜索过程必须把执行结果转化为可复用的证据,改变它下一步探索什么。进化式测试时搜索提供了这个闭环:提出、执行、从经验中学习、在长时程上调整后续扩展。两个耦合的科学问题:下一个该扩展哪个节点(超越贪心的分数最大化)?记忆该如何构建,使被选中的算子拿到的是可行动的证据、而不是不断增长的历史?OpenMLE-Evo 用质量/进展/新颖度的非贪心多因子选择回答前者,用算子条件化、按需合成的有界记忆回答后者。

AIDE、AIRA 与 AIRA₂ 通过树搜索或种群式探索、反复执行与候选精炼,建立了对可执行程序的迭代搜索范式。OpenMLE-Evo 采用 AIRA-Evo 式的种群循环来组合训练好的四个算子,但**重新设计了循环使用执行证据的方式**。原版 AIRA-Evo 的记忆大体是自由文本、急切(eagerly)合成、主要按标量适应度选父代、给不同算子提供大致相同的历史;OpenMLE-Evo 则存储**结构化经验记录**、按质量/进展/新颖度选父代、并为被调用的算子**按需合成有界记忆**。

![图 5:OpenMLE-Evo 搜索 harness。左:搜索树通过 Draft/Improve/Crossover 扩展候选解,每个被评测的节点都配一张结构化经验卡。右:经验卡元数据用于更新全局搜索状态、按质量/进展/新颖度计算父代选择权重、选出下一个父代,并从关键祖先与兄弟节点检索相关记忆,供后续 Improve 操作使用。](/images/reading/frontis-ma1/fig9-evo-harness.png)

### 5.1 结构化经验积累

经验在两个互补的层面积累。**节点级经验卡**:候选在沙盒评测后,harness 从搜索状态与执行结果中确定性地提取核心元数据——候选的出处、表现、执行结果与资源使用——每个节点都有一份紧凑、结构一致的「尝试了什么改动 + 观察到什么结果」的记录。**任务全局经验板(experience board)**:聚合所有已评测节点的卡片,维护种群级统计——已探索的方法族、各族最优候选、探索不足的方向、重复出现的失败、分数趋势与父代图。于是,一个新被选中的节点不仅知道自己的历史,还知道它的祖先、兄弟与相关方法族的表现。卡片与展板共同防止节点级信号淹没在膨胀的搜索空间里:这个可查询的确定性状态,向父代选择供给质量/进展/新颖度信号,向算子条件化检索与按需记忆合成供给谱系、邻域、失败与资源证据。

### 5.2 经验引导的父代选择

原版 AIRA-Evo 的父代采样概率主要来自归一化适应度:虽然仍是随机选择,但搜索几乎完全被节点当前的验证分数驱动,扩展会集中到已经很强的节点上。而「这个节点相对祖先改进了多少」「它是否引入了一个此前探索不足的解法族」这类有信息量的信号,并没有被显式考虑。

OpenMLE-Evo 把经验卡中的确定性元数据转化为三个互补因子:归一化验证分数 $\tilde{s}_i$、相对最强父代的归一化正改进 $\hat{\Delta}_i$、方法族新颖度 $\nu_i$。对被采样岛屿中的候选 $i \in I$,定义经验引导的效用并据此采样下一个父代:

$$U_i = \lambda_s \tilde{s}_i + \lambda_\Delta \hat{\Delta}_i + \lambda_n \nu_i, \qquad P(i \mid I) = \frac{\exp(U_i / \tau)}{\sum_{j \in I}\exp(U_j / \tau)}$$

每次父代选择同时考察:候选当前的解质量、它相对自己谱系取得的进展、它所代表方向上的算法新颖度。这既保持了对高质量解的选择压,也把搜索预算分配给「展现出有意义进展」或「引入了有前景但探索不足方法」的候选。

### 5.3 算子触发的记忆合成

原版 AIRA-Evo 的记忆路径默认对每个已评测节点急切地调用 LLM 总结历史——推理预算花在了后来从未被任何算子选中的节点上,而且总结产生时,本应塑造它的决策上下文还未知。OpenMLE-Evo 把**确定性存储**与**语言模型合成**分开:沙盒评测后只保存经验卡与经验板,把富文本自然语言记忆推迟到某个 Improve / Crossover / Debug 调用选中了相关节点之后;此时才针对被选父代及其检索到的祖先、兄弟或同错误尝试调用记忆模型,生成的方法摘要与父代比较摘要会被缓存。这种按需策略避免了长搜索轨迹上的不必要调用,提高了 LLM 经验提取的效率,也让优化过的、面向操作的提取模板产出更相关、更高质量的记忆。

### 5.4 算子条件化的上下文构建

父代选定后,OpenMLE-Evo 构建一个小的、算子条件化的上下文,而不是追加完整的自由文本历史:

- **Improve**:拼接所选节点的确定性经验记录(验证分数、相对父代的改进、方法族、运行时长、排名、是否现任最优、方向新颖度),加上其近期祖先的**纵向(vertical)轨迹**,与共享至少一个父代的先前候选的**横向(horizontal)兄弟集合**;兄弟集按同一个「分数—改进—新颖度」效用排序,只保留最有信息量的若干——算子因此能把所选轨迹与邻近的替代方案对比,而不是和搜索中不相干的程序对比。
- **Crossover**:对两个父代分别做上述构建,并额外加入方法族互补性提示。
- **Debug**:检索具有相同错误签名的先前尝试,精确匹配不可用时退化为近期尝试。

由全部累积卡片重算的全局经验板,进一步提供当前最优方法族、族级成败统计、探索不足方向、近期改进趋势与反复出现的错误签名。检索到的节点的方法摘要与父代比较摘要惰性生成并缓存,而核心检索信号保持确定性。这种分支局部、有界的上下文,避免了「历史越滚越长」的冗余,给每个算子直接可行动的证据。生成的 prompt 还会注明剩余搜索预算、剩余步数与单次运行执行上限,使这些决策在任务的真实算力约束下保持可行。

**OpenMLE-Evo-Max**(实验部分用到的增强配置)在 Evo 之上做两件事:其一,用一条通用管线从公开竞赛产物中蒸馏可复用的跨任务先验(蒸馏前剔除所有 MLE-Bench 相关来源);其二,在总沙盒算力预算不变的前提下启用异步多 GPU 并行搜索。

## 6 实验

### 6.1 设置

除非另有说明,评测在 MLE-Bench 官方 22 任务的 MLE-Bench Lite 划分上进行;每个 OpenMLE-Evo 配置独立跑 3 次,每任务预算固定为**单张 RTX 4090(12GB 显存)12 小时**——比绝大多数已报告的 MLE-Bench 评测所用的每任务沙盒算力都小。三个聚合指标:**Valid Rate**(22 个任务中产出有效提交的平均个数,$x/22$);**Medal Average**(拿到任一 Kaggle 奖牌的任务比例均值);**Human Rank**(提交方案超过人类排行榜参与者的比例,跨任务与运行取平均,越高越好)。

> **译注**:12GB 显存的 4090 跑 12 小时这个预算相当克制——它衡量的是「agent 的搜索与学习能力」,而不是「砸卡」。这也让整套系统的效率数字(后文的 token 节省)更有分量。

### 6.3 长时程自我改进

跨 harness 的奖牌率随时间演化(22 任务、累计沙盒时间 12 小时)显示:Frontis-MA1-35B + Evo-Max 在整个长时程搜索中持续提升,而且解对最终测试的泛化很强——验证集 68.18%,最终测试反而达到 71.21%。

两个逐轨迹的案例研究更能说明机制:

**叶分类(leaf-classification)**:同一 OpenMLE-Evo 协议下,对比模型要么在低 Human Rank 处平台化,要么有改进但够不到奖牌线。Frontis-MA1-35B 则先用两次 Debug 建立可行的图像与表格分支(修多分类标签编码 + 稳定 LightGBM;覆盖全部 99 类、去掉 ResNet18 分支里无关的颜色抖动),再用 Improve 把 EfficientNet 嵌入与 192 个工程化特征融合成多模态,接着两次 Crossover 保留互补证据(混合融合 → 加增强/早停/TTA 的鲁棒融合),最后在结构稳定后用一次 Improve 把融合表示升级到 ConvNeXt-Tiny——这最后一次操作带来最大单步跳变。**后期的 Crossover 与 Improve 贡献了总验证增益的 85.0%**:长时程被花在积累与重组分支证据上,而不是反复修补同一个程序。最终验证 Human Rank 0.7713,held-out 0.9455 获铜牌;最强对比仅 0.6303 且无牌。

![图 7:leaf-classification 上的跨模型搜索轨迹。左:同一 epoch 下 best-so-far 验证 Human Rank 随累计沙盒时间的变化;编号操作卡展示 Frontis-MA1-35B 轨迹的关键节点。右:held-out best-of-3 最终测试,Frontis-MA1 获铜牌。](/images/reading/frontis-ma1/fig13-leaf-trajectory.png)

**mlsp-2013-birds**:对比轨迹停留在第一个可行解附近,Frontis-MA1 则把「修提交」当起点,随后构建专门的音频分支。这里记忆的关键作用在**筛选而非数量**:它记住了哪些分支贡献了鲁棒解析、类别不平衡处理、数据增强与表示质量,并把一条较差的 ResNet50 方向标记为「应避免的证据」。Improve 与 Crossover 因此能组合兼容的收益,而不是继承一团不分彼此的历史——两者合计贡献总验证改进的 91.9%。最终验证 0.7284,held-out 0.8889 获银牌。

### 6.4 解的上限

收益不限于把更多解推过铜牌线:更强的系统也产出更大比例的**金牌**解。35B 主模型上,后训练与 Evo-Max 不只是扩大奖牌覆盖,而是把成功解推向金牌;30B 复现同一方向;固定模型的 GLM-5.2 / MiniMax M3 比较表明该模式也延伸到搜索改进。与外部系统比,Frontis-MA1-35B + Evo-Max 的金牌率超过 Claude Opus 4.8 + Claude Code 与 Gemini 3.5 Flash + Gemini CLI,追平 Kimi K3。

### 6.5 搜索效率与机制

与原版 AIRA-Evo 的配对比较(同一 Frontis-MA1-35B checkpoint、同种子、同 12 小时预算,每 harness 66 个任务—运行):

- **搜索成本更低**:模型 token 总消耗从 129.3M 降到 75.3M(−41.7%),prompt token 从 83.5M 降到 41.5M(−50.3%),而评测节点数只从 3,430 降到 3,004(−12.4%)——token 的降幅远大于节点数,说明节省主要来自「每次扩展更便宜」,而非提前终止搜索。
- **搜索产出更高**:尽管评测节点更少,刷新验证最优的次数从 229 升到 246;每百万模型 token 的刷新次数从 1.77 升到 3.27(**+84.3%**);Improve 操作刷新最优的比例从 4.73% 升到 9.36%(+98.1%)。
- **有界的操作上下文**:Improve 的平均序列化 prompt 长度从 102.8K 字符降到 35.7K(−65.3%),99 分位从 389.0K 降到 54.3K(−86.1%);Crossover 均值 −60.6%、99 分位 −81.3%。尾部压缩尤其明显——结构化、算子条件化的记忆阻止了「长历史被反复序列化进每个请求」。

![图 8:原版 AIRA-Evo(灰)与 OpenMLE-Evo(青)在 66 个配对任务—运行上的搜索效率对比。A:各资源指标归一化;B:验证轨迹产出;C:序列化 prompt 长度(对数轴)。](/images/reading/frontis-ma1/fig16-efficiency.png)

两个机制案例:

**定向 Crossover 跳出单分支 Debug 循环**(nomad2018):原版 AIRA-Evo 在 Draft 失败后沿单一谱系连续 Debug 七次,每次重试都继承不断膨胀的完整历史,最终验证 RMSE 0.06633 / held-out 0.06096。OpenMLE-Evo 在第 81 步从互补证据构造定向 Crossover:一个父代贡献原子性质、动态共价边与晶胞体积(0.06309),另一个贡献能解析不规则 .xyz 几何的鲁棒解析器(0.06573);横向记忆还把「RDF 缓存 TypeError」与「3328×94 特征维度不匹配」标记为负面证据,避免它们被悄悄序列化进子代上下文。生成的子代把物理启发的 GNN 与鲁棒解析器、密度描述符、cosine 调度组合在一起,验证 0.06087 / held-out 0.05410,分别比原轨迹好 8.2% 与 11.3%。

**三因子选择保住互补父代**(right-whale):原版里两条独立修复分支达到验证 AUC 0.94656 与 0.85546,纯分数选择只留下强者。OpenMLE-Evo 第 10 步的候选池里,父代 A 以 0.99187 领跑(更深的 ResNet-SE + 64-Mel + AMP + TTA),父代 B 分数仅排第六(0.98773)但**增益排第一**(相对自己父代 +0.00568),保留着有前景的 Log-Mel + Delta/Delta-Delta 时间通道表示。按 Score/Gain/Novelty 权重 1.0/0.6/0.3,B 的效用升到第一,在同一个十候选池里的被选中概率从纯分数 softmax 的 10.47% 升到 17.09%(相对 +63.2%)。B 随后被选中做 Improve,子代验证 0.99203、held-out 0.99386。这个池内概率重算直接展示了选择器的作用:额外因子并不强行让低分分支胜出,而是让「高增益、结构上不同」的分支活得足够久,等到被选中与精炼。

### 6.6 元能力与迁移

**跨模态元能力。** 把 22 个 MLE-Bench Lite 任务按图像、文本、表格/结构化、音频、多模态分成五组:同一 harness 下,Frontis-MA1-35B 相对基座在全部五组都提高了平均 Human Rank,且没有任何一组的 Medal Rate 下降;新增的 14 枚奖牌分布在每一组(+2/+4/+1/+4/+3)——总收益不是某一种模态解释的。

**向 NatureBench 泛化。** NatureBench 评测 coding agent 能否复现或改进已发表的科学结果(90 个容器化任务,来自 Nature 系论文、六个科学领域;测试真值与论文方法藏在宿主侧评测器后)。用固定的 10 任务 NatureBench Lite 子集做迁移研究,保留其容器、隐藏评测器、有效性规则、禁网设置与每任务 4 小时预算;OpenMLE-Evo 的 NatureBench 适配器只改任务接口、资源调度与反馈管线,不暴露隐藏标签与论文解法。指标为方向归一化的相对差距 $g = \mathrm{dir}\cdot(m - m_{\text{SOTA}}) / |m_{\text{SOTA}}|$,报告 Match-SOTA(All M,$g \geq 0$)与 Surpass-SOTA(All S,$g > 0.1$)。

迁移结果把两个组件的贡献分开:固定适配器,换入 Frontis-MA1-35B 把 All M 从 5/10 提到 7/10(All S 从 2/10 到 3/10);固定基座模型,换入 OpenMLE-Evo 适配器把 All M 从 2/10 提到 5/10(All S 从 1/10 到 2/10)。组合系统追平了 GPT-5.4、GLM-5.1、MiniMax-M3 在该子集上的 3/10 All S 与 7/10 All M,超过 DeepSeek-V4-Pro、Claude Opus 4.6、MiniMax-M2.7 的已报告配置。蛋白质变异效应预测的逐轨迹案例里,Frontis-MA1 在 11 个 assay 实例上达到 $g = 0.1161$(基座仅 0.0243):三因子选择器没有贪心死磕现任最优,而是回访了一条分数/近期增益/新颖度仍有前景的不同分支,纵横向记忆保住成功的理化特征、暴露邻近的超时/KeyError/嵌套映射失败,最终 Improve 节点加入由训练标签衍生的位置先验与五折 LightGBM 集成——全程不接触隐藏测试标签与论文解法。

## 7 相关工作(节译)

**自动研究系统与评测目标。** 从端到端科学工作流、agentic 树搜索到算力受限的模型训练循环(Karpathy 的 autoresearch、AI Scientist 等),自动研究系统日益自动化假设形成、实验与产物生成;RE-Bench、PostTrainBench、MLGym、PaperBench、NatureBench 等 benchmark 各自隔离了研究回路的不同切片。**可执行 MLE 环境与任务资源。** 经典 AutoML 在预定义空间上优化,LLM MLE agent 则以开放式、代码中介的实验方式运作;MLE-Dojo、MLE-Smith、SandMLE 把执行反馈的供给规模不断扩大,但「可执行任务」本身并不规定经验该如何转化为可复用的模型能力。**推理时支架与进化搜索。** AIDE/AIRA 系确立了结构化搜索的价值,但通常依赖冻结骨架(或其 prompt)提供的变换行为;OpenMLE-Evo 组合的是**为搜索中同一角色显式训练**的算子。**从可执行经验学习 MLE agent。** RLVR 在数学与代码上证明了可验证奖励的价值并扩展到长程 agent 任务;MLE 方向的 AceGRPO、MLE-RL、ML-Agent 等证明 MLE 经验可以被模型内化,但没有一个把「算子训练」与「长时程搜索」围绕共享接口组织起来。OpenMLE 的贡献正在这些方向的交界面:已验证的进化经验后训练同一批程序变换算子,而这些算子随后主宰进化搜索,形成学习与推理之间的元进化耦合。作者也明确强调:这是「研究 RSI 进展的可复现试验场」,而非声称已实现通用的自主 RSI。

## 8 局限与未来工作

作者列出五个他们认为对弥合 RSI 差距最关键的能力边界:

1. **改进「改进者」需要更丰富的目标。** 当前系统主要从「已执行解的测量结果」学习——这能说明程序能不能跑、分数多高,却不能完整刻画一个研究方向是否有前景、可泛化、鲁棒、值得追加算力。系统因此更擅长优化解法,而不擅长判断哪些想法值得追求。更强的改进者需要能表示假设质量、推理过程、批判与可迁移研究策略的目标。
2. **进化搜索与通用 coding agent 的融合。** 当前系统通过外部进化 harness 组合训练好的算子。这种分离让训练与搜索可行,但也限制了模型自主发起的动作与交互范围。更进一步需要把种群式探索与灵活的 agentic 问题求解放进统一框架。
3. **更广地参与 AI 开发。** 当前环境只让 agent 改进外部 ML 产物,参与的是 AI 开发过程中有限的一部分。更接近 RSI 需要 agent 参与更大的份额——尤其是语言模型自身的改进。
4. **让进化系统本身进化。** OpenMLE 里,进化作用在候选解上,而进化系统本身基本固定。走向 RSI 的又一步,是把进化系统本身也变成进化的对象。
5. **节点扩展中对经验更充分的利用。** 经验引导的节点扩展仍是初步原型:经验卡记录了丰富的确定性元数据,但父代选择只用了三个因子(质量、父代相对改进、方法族新颖度)。未来可以引入更多信号、学习与任务相关的因子权重(而非固定权重);更广义地,让搜索策略自己发现哪些经验信号有预测力,是从「手工设计的经验引导」走向「能改进自身搜索行为的进化系统」的一条有前景路径。

## 9 结论

OpenMLE 把可验证环境、算子后训练与测试时进化连接在一个经过验证的工作流里:OpenMLE-Gym 提供质量门控任务、隔离执行与任务专属评测;OpenMLE-ERL 通过执行 grounded 的 SFT 与 RL 学习 Draft / Improve / Debug / Crossover 变换;OpenMLE-Evo 用结构化经验、多因子父代选择与算子条件化记忆把同一组算子组合成长时程搜索。共享的算子与执行接口,使 Frontis-MA1-35B 既是训练栈的产物,又是其进化 harness 的变异引擎。结果表明模型学习与搜索提供了互补收益,机制分析显示长时程后段的精炼与重组带来持续增益,且两者都能迁移到竞赛式 MLE 之外。连同释放的全栈,OpenMLE 是可执行 AI4AI 中研究元进化的可复现试验场。

> **译注**:读完可以把这篇放回「自我改进」的坐标系里:Seed 解决的是「轨迹内部的事后监督如何参数化」,SWE-1.7 展示的是「大规模 agentic RL 的工程稳定性」,而 Frontis-MA1 回答的是「搜索与训练如何共享同一套动作词汇表」——三者拼起来,正好是 RSI 从口号变成工程问题的一条完整线索。另一个值得记住的数字:用 4090 12GB × 12 小时这种「平民预算」做出 71% 奖牌率,说明在 MLE 这类任务上,搜索与经验机制带来的杠杆,目前仍然大于单纯堆模型规模。
